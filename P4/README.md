# Weather — заготовка P4

Живі дані WeatherAPI: запит, мапер, чотири стани екрана, кеш і оновлення.
React Native + **Expo SDK 57**, TypeScript, expo-router, TanStack Query v5.
**Цей файл і є завдання** — опис роботи та кроки самоперевірки нижче.

Заготовка запускається й **відразу використовує `useQuery`**. Провайдер,
`queryKey`, `queryFn` і початковий спінер уже підключені. Після завантаження
видно три міста без погоди: `0°C`, порожню умову й місце замість іконки —
мапер ще не написаний. Стани помилки й порожнього списку, свіжість кешу та
оновлення пальцем ви додасте самі. Навігація P3 вже готова.

## Як працювати

Робіть TODO(1)–TODO(5) за порядком. Спочатку лишайте `USE_MOCKS = true`:
запит можна написати без робочого Wi-Fi, а мапер — перевірити на збереженій
відповіді. У коментарях біля TODO є каркас і підказки.

**Уся робота зі станом запиту — через один `useQuery`.** Не потрібно спочатку
писати `useEffect`, копіювати результат у `useState` чи вручну перемикати
`loading` і `refreshing`. `fetch` залишається в мережевому шарі; екран отримує
дані й стани через Query. Помилка має бути винятком із `queryFn`, а не `[]`.

### Як читати стан useQuery

| Умова | Що показати |
|---|---|
| `isPending` | Початковий спінер; ця гілка вже готова |
| `isError && data === undefined` | Текст `error.message` і кнопку повтору |
| `data !== undefined && data.length === 0` | Окремий порожній стан, наприклад «Немає міст» |
| Є непорожні `data` | Картки міст |

Перевіряйте умови саме в цьому порядку. `undefined` означає, що успішної
відповіді ще немає; `[]` означає успішну відповідь без міст. Не визначайте
порожній стан лише через `(data ?? []).length`: так помилка стане «порожньо».

`isPending` і `isRefetching` мають різні ролі: перший відповідає за початковий
екран, другий — за індикатор повторного запиту. При оновленні список лишається
видимим. Якщо повторний запит завершився помилкою, наявні дані теж залишаються:
повноекранна помилка потрібна лише тоді, коли `data === undefined`.

`retry: false` уже задано: автоматичних повторів після невдалого запиту немає.
Повтор за кнопкою чи жестом — через `refetch`. Ручний `refetch` працює й тоді,
коли п'ять хвилин свіжості ще не минули. `staleTime` не є таймером опитування:
сам по собі він не запускає запит кожні п'ять хвилин.

Підказка: [довідка useQuery v5](https://tanstack.com/query/v5/docs/framework/react/reference/useQuery).

## Як перевірити й отримати чотири скриншоти

У `src/lib/config.ts` є готовий перемикач `DEMO_STATE`. Він потрібний для
перевірки інтерфейсу; писати власні моки чи псувати API-ключ не треба.
`empty` і `error` мають пріоритет над `USE_MOCKS` і не роблять HTTP-запитів.
У моках та навчальних сценаріях є затримка 1,5 с для скриншота завантаження;
у звичайному режимі живих даних штучної затримки немає.

**Після кожної зміни `USE_MOCKS` або `DEMO_STATE` зробіть повний Reload через
меню розробника Expo Go.** Fast Refresh може зберегти попередній результат
у кеші. Reload починає перевірку без попередніх даних у пам'яті.

| Перевірка | Налаштування і дії | Очікуваний результат |
|---|---|---|
| Завантаження | `USE_MOCKS = true`, `DEMO_STATE = 'normal'`, Reload | Спінер, потім список; зробіть скриншот спінера |
| Дані | `USE_MOCKS = false`, `DEMO_STATE = 'normal'`, Reload, дочекайтеся відповіді | Три міста з живою погодою й іконками; скриншот |
| Порожньо | `DEMO_STATE = 'empty'`, Reload | Окреме повідомлення без карток і без помилки; скриншот |
| Помилка | `DEMO_STATE = 'error'`, Reload | Текст навчальної помилки й кнопка повтору; скриншот |
| Повтор після помилки | У режимі `error` натисніть «Спробувати ще» | Новий запит, потім знову помилка: сценарій досі примусово помилковий |
| Оновлення | Поверніть `normal`, зробіть Reload, дочекайтеся списку й потягніть вниз | Індикатор повторного запиту; картки лишаються видимими |

Навчальна помилка перевіряє лише інтерфейс. Окремо перевірте TODO(1): тимчасово
передайте неіснуюче місто, наприклад `zzzz-no-such-city-12345`, замість
`coordsQuery(city)` у `fetchOne`. Увімкніть живі дані, зробіть Reload:
на екрані має бути повідомлення WeatherAPI, а не просто «HTTP 400».
Після перевірки поверніть `coordsQuery(city)`.

Для кешу перевірте `staleTime: 5 * 60 * 1000` у коді.
Перейдіть на інший таб і поверніться: список має лишитися доступним.
Сам перехід між табами ще не доводить роботу кешу — таб може залишатися
змонтованим. Не робіть Reload під час цієї перевірки: він очищає кеш у пам'яті.

Перед здачею поверніть **`USE_MOCKS = false`, `DEMO_STATE = 'normal'`**.
Скриншоти завантаження, порожнього стану й помилки можна робити у навчальних
режимах; скриншот даних — зі справжнім WeatherAPI.

## Як запустити

Потрібні **Node.js LTS** на ноутбуці та **Expo Go** на телефоні.

```bash
npm install
npx expo start          # QR-код у терміналі
```

Відскануйте QR-код камерою (iOS) або Expo Go (Android). Різні Wi-Fi мережі —
`npx expo start --tunnel`. Версії залежностей у `package.json` не змінюйте.

Перед здачею виконайте `npm run typecheck`. Він перевіряє типи;
правильність станів і поведінку на телефоні перевірте за таблицею вище.
